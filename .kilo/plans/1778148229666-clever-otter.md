## Detailed Implementation Specs

### Phase 1: SQLite Persistence

**New files:**
- `backend/app/shared/database.py` — SQLite connection, table creation, CRUD operations
- `backend/app/features/pipeline/repository.py` — Investigation repository (save/load/list)

**Modified files:**
- `backend/app/features/pipeline/service.py` — Replace `_pipeline_store` dict with repository calls
- `backend/app/features/pipeline/stats.py` — Query from DB instead of dict
- `backend/app/features/pipeline/mitre_stats.py` — Query from DB
- `backend/app/features/report_export/service.py` — get_investigation now reads from DB
- `backend/app/features/soar_integration/service.py` — same
- `backend/app/features/pipeline/decision.py` — same
- `backend/requirements.txt` — Add `aiosqlite>=0.20.0`
- `backend/app/main.py` — Initialize DB on startup

**Schema:**
```sql
CREATE TABLE IF NOT EXISTS investigations (
    investigation_id TEXT PRIMARY KEY,
    alert_json TEXT NOT NULL,
    state_json TEXT NOT NULL,
    status TEXT NOT NULL,
    severity TEXT NOT NULL,
    started_at TEXT NOT NULL,
    completed_at TEXT,
    total_processing_time_ms REAL DEFAULT 0,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);
```

**Key design decisions:**
- Store full `PipelineState` as JSON blob (simple, no schema migration needed)
- Keep `_pipeline_store` dict as write-through cache for SSE streaming performance
- On startup, load all investigations from DB into cache
- Use `aiosqlite` for async SQLite access (no external DB server needed)
