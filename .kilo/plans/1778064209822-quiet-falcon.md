## Enhancement 4: Feedback Loop — Analyst Decision Improves Future Triage (Priority: HIGH)

**Impact:** "Self-improving" is the #1 differentiator of top AI SOC tools (Simbian, Conifers). This shows ORIGINALITY.

### Concept:
When an analyst makes a decision (approve/escalate/reject), store that feedback and use it to enrich future triage prompts. This creates a closed-loop learning system.

### Files Affected:
- `backend/app/features/pipeline/decision.py` — already records decisions
- `backend/app/features/pipeline/feedback.py` — NEW file
- `backend/app/features/triage/service.py` — inject feedback context

### Implementation:
```python
# backend/app/features/pipeline/feedback.py
"""
SOCsentinel — Feedback loop for self-improving triage.

Stores analyst decisions and uses them to enrich future triage prompts
with historical context about similar alerts.
"""

from typing import Any
from app.core.logger import get_logger

logger = get_logger(__name__)

# In-memory feedback store (production: database)
_feedback_store: list[dict[str, Any]] = []

def record_feedback(
    alert_severity: str,
    alert_rule_name: str,
    triage_classification: str,
    analyst_decision: str,
    confidence: float | None,
) -> None:
    """Record analyst feedback for future triage improvement."""
    _feedback_store.append({
        "severity": alert_severity,
        "rule_name": alert_rule_name,
        "ai_classification": triage_classification,
        "analyst_decision": analyst_decision,
        "confidence": confidence,
    })

def get_relevant_feedback(rule_name: str, limit: int = 3) -> list[dict]:
    """Get recent analyst feedback for similar alerts."""
    relevant = [
        f for f in _feedback_store
        if f["rule_name"] == rule_name
    ]
    return relevant[-limit:]
```

#### detection_system.txt Prompt:
```
You are the SOCsentinel Detection Agent — a Detection Engineering specialist.

Your role is to generate deployable Sigma rules from investigation findings.
Sigma is the industry-standard format for SIEM detection rules.

Given MITRE ATT&CK technique mappings and observable data, generate a complete,
syntactically valid Sigma rule.

Output MUST be valid YAML in this format:
title: "<rule name>"
name: "<unique rule identifier>"
status: stable|test|experimental
level: informational|low|medium|high|critical
description: "<what this detects>"
tags:
  - attack.<tactic>
  - attack.<technique>
  - attack.<subtechnique>
logsource:
  product: <siem product>
  service: <service name>
detection:
  selection:
    <field>: <value>
  condition: <expression>
fields:
  - <list of fields to extract>
falsepositives:
  - <known false positive scenarios>
level: <severity level>

Guidelines:
- Generate syntactically valid Sigma YAML
- Map to correct MITRE ATT&CK technique IDs
- Include proper logsource context (product/service)
- Add known false positives to reduce alert fatigue
- Keep detection specific to avoid high false positive rates
```

#### service.py Implementation:
```python
async def generate_detection(
    alert_data: dict,
    mitre_result: dict,
    evidence_result: dict,
) -> dict[str, Any]:
    """Generate Sigma detection rules from investigation."""
    llm = create_llm_client(model_name=settings.qwen3_7b_model)
    system_prompt = load_prompt("detection_system")
    
    user_message = build_detection_prompt(alert_data, mitre_result, evidence_result)
    
    result = await run_agent(
        agent_name="Detection",
        llm=llm,
        system_prompt=system_prompt,
        user_message=user_message,
    )
    return result
```
